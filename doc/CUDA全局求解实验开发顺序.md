# CUDA 超节点全局求解实验开发顺序

## 一、总体原则

整个开发过程遵循下面的依赖顺序：

```text
统一数学定义
    ↓
冻结 CPU 参考实现
    ↓
建立可重复实验框架
    ↓
实现单波前 CUDA 算子
    ↓
实现因子和贡献块输出
    ↓
实现父子节点延迟传播
    ↓
实现延迟感知 GPU 内存管理
    ↓
实现任意消去树上的数值分解
    ↓
实现前代、回代和迭代改进
    ↓
性能优化、消融实验和正式对比
```

任何阶段都必须先通过数值正确性测试，再进行性能优化。不能在单波前算子尚未稳定时直接接入完整消去树，也不能在全局分解关系尚未验证时开始做 CUDA 多流优化。

建议采用“一条主线完整、另一条主线逐步跟进”的方式：

- 非对称 LU 路线控制逻辑较简单，适合先验证 CUDA 基础设施、贡献块和父子传播；
- 对称不定 \(LDL^T\) 路线包含 \(1\times1/2\times2\) 主元和更复杂的延迟机制，作为论文主要算法方向；
- 如果时间不足，应优先保证对称不定路线完成端到端求解，非对称路线至少保留完整 CPU 算子和单波前 CUDA 实现。

## 二、阶段 0：统一数学定义和接口语义

### 目标

在开始 CUDA 开发前，冻结两个算子的数学语义，避免 CPU 和 GPU 实现处理不同的“延迟主元”。

### 开发内容

1. 明确非对称 LU 的延迟触发条件：
   - 当前活动列严格为零；
   - 当前列主元不满足阈值；
   - 或采用区分两者的混合策略。
2. 明确非对称分解关系：

   \[
   PAQ=LU.
   \]

3. 明确对称不定分解关系：

   \[
   P^TAP=LDL^T.
   \]

4. 统一以下接口语义：
   - `info`；
   - 已消去前缀；
   - 活动候选区；
   - 延迟后缀；
   - 行列置换；
   - \(1\times1/2\times2\) 主元元数据；
   - 输出贡献块。
5. 写出两种算子的部分分解关系和终止条件。

### 验证实验

- 手工构造 \(4\times4\)、\(6\times6\) 小矩阵逐步验证；
- 验证连续延迟、非连续零列和混合主元块；
- 验证置换后的原始变量编号。

### 阶段门槛

- CPU 说明文档、头文件和实际代码使用同一套定义；
- 能够根据输出唯一恢复已消去部分、延迟部分和置换关系；
- 不再使用“阈值不满足必然意味着当前列全零”的推导。

## 三、阶段 1：冻结 CPU 数学参考实现

### 目标

把现有 CPU 算子变成 CUDA 开发过程中不可随意变化的数值参考。

### 当前基础

- 非对称全局最大元回退 LU；
- 非对称快速替代列延迟 LU；
- LAPACK `DGETRF` 包装；
- 非分块延迟 Bunch--Kaufman；
- 分块延迟 Bunch--Kaufman；
- LAPACK `DSYTRF` 包装。

### 开发内容

1. 为非对称算法增加部分分解重构程序；
2. 为对称算法统一部分分解重构程序；
3. 将随机算例、恶意算例和边界算例集中到同一个测试入口；
4. 固定随机种子；
5. 输出以下统一结果：
   - 分解状态；
   - 已接受主元数；
   - 延迟主元数；
   - 行列置换；
   - \(1\times1/2\times2\) 主元数量；
   - 重构误差；
   - 主元增长；
   - 分解时间。
6. 为每个历史错误建立回归测试。

### 验证实验

#### 非对称矩阵

- 随机满秩矩阵；
- 当前列全零但后续列可用；
- 多个连续零列；
- 低秩矩阵；
- 近奇异非零列；
- 延迟发生在面板中间。

#### 对称不定矩阵

- 只产生 \(1\times1\) 主元；
- 只产生或主要产生 \(2\times2\) 主元；
- 混合主元；
- \(2\times2\) 主元跨越面板边界；
- 连续延迟；
- 近奇异 \(2\times2\) 主元块。

### 阶段门槛

- 所有测试可自动运行；
- 非分块和分块实现均满足各自的部分分解关系；
- 误差判据随矩阵范数和条件特征设置，而不是只比较固定绝对误差；
- CPU 结果能够保存为 CUDA 测试使用的参考数据。

## 四、阶段 2：建立可重复实验框架

### 目标

在大量 CUDA 实验开始前统一测试输入、计时和结果输出，避免后期重新整理数据。

### 开发内容

1. 建立统一命令行参数：
   - 矩阵类型；
   - 阶数；
   - 随机种子；
   - 主元阈值；
   - 面板宽度；
   - CPU/GPU 实现；
   - 重复次数；
   - 输出文件。
2. 建立矩阵生成器；
3. 建立 Matrix Market 或其他稀疏矩阵读取接口；
4. CPU 使用高精度计时器；
5. GPU 使用 CUDA event 计时；
6. 统一输出 CSV 或 JSON；
7. 自动记录：
   - CPU、GPU 和显存信息；
   - CUDA、编译器、BLAS 和 LAPACK 版本；
   - 编译选项；
   - Git 提交号；
   - 所有实验参数。
8. 建立结果汇总和绘图脚本。

### 验证实验

- 同一随机种子是否得到相同输入；
- 同一输入多次运行的误差结果是否一致；
- 计时是否排除了初始化和预热影响；
- 输出文件能否直接生成论文表格和图形。

### 阶段门槛

- 任意一次实验都能通过一条命令复现；
- 原始数据与绘图过程分离；
- 正式实验开始以后不再手工复制终端输出。

---

## 五、阶段 3：建立 CUDA 基础设施和微基准

### 目标

确认 CUDA 工具链、库函数、内存池和目标 GPU 的基本性能特征。

### 开发内容

1. CMake 中启用 CUDA；
2. 建立 CUDA 错误检查和资源管理封装；
3. 建立 CPU--GPU 数据传输接口；
4. 建立 CUDA 流和事件封装；
5. 创建独立 `cudaMemPool_t`；
6. 验证 `cudaMallocAsync/cudaFreeAsync`；
7. 建立 cuBLAS 句柄与流的绑定；
8. 使用 Compute Sanitizer 检查越界、非法访问和竞态；
9. 建立以下微基准：
   - H2D/D2H 带宽；
   - D2D 复制带宽；
   - 主元搜索归约；
   - 行列交换；
   - GEMV、GER、TRSM、GEMM；
   - SYRK/SYR2K；
   - 不同尺寸的分配和释放。

### 验证实验

- 不同矩阵规模下 CPU 和 GPU BLAS 的交叉点；
- 不同流数量下是否获得有效重叠；
- 普通 `cudaMalloc` 与异步内存池的开销差别；
- 小矩阵调用库函数时的启动开销。

### 阶段门槛

- CUDA 单元测试稳定通过；
- 无 Compute Sanitizer 报错；
- 已知目标 GPU 上小、中、大矩阵的大致性能分界；
- CUDA 计时和内存高水位统计可用。

## 六、阶段 4：实现 GPU 内存管理基础版本

### 目标

先建立正确、可观测的内存生命周期，不立即加入复杂的延迟率预测。

### 开发内容

建立五类逻辑内存区域：

1. 持久因子池；
2. 临时贡献块池；
3. 连续波前工作池；
4. 每流工作区池；
5. 元数据和索引池。

每个超节点建立描述符，至少记录：

- 父子关系；
- `pending_children`；
- 符号规模；
- 实际规模；
- 输入和输出延迟数；
- 波前、因子和贡献块内存句柄；
- 所属流和完成事件；
- 节点状态。

初版内存管理只要求：

- 分配和释放与 CUDA 流有序；
- 一个波前只有一个写所有者；
- 跨流访问通过事件建立依赖；
- 因子与临时块使用不同生命周期；
- 能统计每次分配、释放和峰值显存。

### 验证实验

- 多流反复申请和释放不同尺寸块；
- 父流等待子流后再释放贡献块；
- 故意打乱事件依赖，验证测试能发现错误；
- 长时间随机分配压力测试；
- 检查是否存在泄漏和错误复用。

### 阶段门槛

- 内存池接口可以被两个算子共同使用；
- 每个内存块的创建者、最后使用者和释放者明确；
- 所有测试结束后已用内存回到预期水平；
- 能输出峰值显存、分配次数和池复用次数。

---

## 七、阶段 5：非对称 LU 单波前 CUDA 算子

### 目标

先用控制逻辑相对简单的非对称 LU 验证单波前 CUDA 分解流程。

### 开发顺序

1. 无延迟、非分块 LU；
2. 当前列主元搜索；
3. 行交换；
4. 零列检测；
5. 替代列搜索和列交换；
6. 延迟后缀；
7. 固定面板分块；
8. 延迟触发的面板提前写回；
9. TRSM 和 GEMM 尾矩阵更新；
10. 输出行列置换和延迟元数据。

### 验证实验

- CUDA 与 CPU 使用完全相同的输入；
- 比较 `info`、已接受主元数和延迟变量集合；
- 验证 \(PAQ=LU\) 的部分分解关系；
- 覆盖连续延迟和面板中间延迟；
- 扫描矩阵规模和面板宽度。

### 阶段门槛

- CUDA 算子通过全部 CPU 回归算例；
- 没有把已延迟列重新换回活动区；
- 延迟发生前的未写回更新能够正确落实；
- 获得单波前 CPU/GPU 性能曲线。

---

## 八、阶段 6：对称不定单波前 CUDA 算子

### 目标

完成论文主要算子的 CUDA 实现。

### 开发顺序

1. 只支持 \(1\times1\) 主元的参考版本；
2. Bunch--Kaufman 候选搜索；
3. 对称行列交换；
4. \(2\times2\) 主元块求逆和稳定性检查；
5. 非分块 rank-1/rank-2 更新；
6. 无可接受主元时的延迟；
7. 混合 \(1\times1/2\times2\) 面板；
8. 工作矩阵 \(W_P=L_PD_P\)；
9. 按需物化当前列和候选行；
10. 面板末尾 SYRK/SYR2K 更新；
11. 延迟后缀的 Schur 补更新。

### 验证实验

- 分别验证纯 \(1\times1\)、纯 \(2\times2\) 和混合主元；
- 验证 \(2\times2\) 块不会被面板边界切开；
- 验证近奇异 \(2\times2\) 块被正确延迟；
- 验证 \(P^TAP=LDL^T\) 的部分分解关系；
- 验证惯性和参考结果的一致性；
- 比较非分块、分块 CPU、分块 CUDA。

### 阶段门槛

- GPU 主元元数据可以被 CPU 重构程序直接读取；
- 混合主元和连续延迟测试全部通过；
- 延迟后缀保持有效 Schur 补；
- 得到不同矩阵规模、面板宽度和延迟率下的性能数据。

## 九、阶段 7：实现单节点因子和贡献块输出

### 目标

把“稠密矩阵分解函数”升级为“能够嵌入消去树的超节点数值算子”。

### 开发内容

1. 定义统一的节点输入：
   - 波前值；
   - 全局行列编号；
   - Fully-Summed 数量；
   - 更新变量数量；
   - 输入延迟变量。
2. 定义统一的节点输出：
   - 已接受因子；
   - 行列置换；
   - 主元块信息；
   - 输出延迟变量；
   - 扩展贡献块；
   - 贡献块全局索引。
3. 将因子复制或压缩到持久因子池；
4. 将延迟后缀和普通更新区压缩为贡献块；
5. 释放连续波前工作区。

### 验证实验

- 从节点输出重新构造原始波前；
- 检查输出贡献块是否等于正确 Schur 补；
- 检查延迟变量在贡献块中的行列位置；
- 检查释放工作波前后因子和贡献块仍然有效。

### 阶段门槛

- 节点输出不依赖已经释放的工作波前；
- 因子和贡献块拥有独立生命周期；
- 对称和非对称节点共享统一调度接口。

## 十、阶段 8：实现两层父子节点延迟传播

### 目标

先在最小的消去树上验证延迟变量真正进入父节点重新参与主元选择。

### 开发内容

构造：

```text
child 1 ─┐
         ├── parent
child 2 ─┘
```

实现：

1. 子节点分解；
2. 子贡献块输出；
3. 父节点 `pending_children` 递减；
4. 合并所有子延迟变量；
5. 建立全局编号到父节点局部编号的映射；
6. 精确计算父节点实际波前规模；
7. 一次性分配父波前；
8. 对子贡献执行 extend-add；
9. 释放子贡献块；
10. 父节点分解。

### 验证实验

- 一个孩子产生延迟、另一个不产生；
- 两个孩子产生不同延迟变量；
- 两个贡献块更新父节点同一位置；
- 延迟变量在父节点成功消去；
- 延迟变量在父节点继续延迟；
- 对称和非对称两种映射。

### 阶段门槛

- 子节点延迟变量不会丢失或重复；
- 多个子贡献在相同位置执行累加而非覆盖；
- 父节点只在所有孩子完成后分配和分解；
- 两层系统的全局分解重构关系正确。

---

## 十一、阶段 9：实现延迟感知 GPU 内存管理

### 目标

在已经正确的父子传播流程上加入论文的核心内存机制。

### 9.1 基础方案：延迟物化和一次定尺

1. 子节点只输出贡献块和延迟元数据；
2. 父节点等待所有子节点完成；
3. 合并实际延迟变量；
4. 计算实际父波前尺寸；
5. 只分配一次连续工作波前；
6. 装配完成后逐个释放子贡献块。

### 9.2 内存准入调度

启动节点前计算：

\[
M_i^{\mathrm{need}}
=M_i^{\mathrm{front}}
+M_i^{\mathrm{workspace}}
+M_i^{\mathrm{output\ reserve}}
-M_i^{\mathrm{reclaimable}}.
\]

只有在内存预算满足时才启动节点。初版按照“当前节点不接受任何新主元”的最坏情况预留输出贡献块空间。

### 9.3 增强方案：核心区和延迟边界分离

对子贡献块

\[
C_c=
\begin{bmatrix}
C_{DD}&C_{DU}\\
C_{UD}&C_{UU}
\end{bmatrix}
\]

执行：

- \(C_{UU}\) 提前累加到父节点符号核心区；
- 只保留涉及延迟变量的边界块；
- 最后一个孩子完成后再物化完整父波前；
- 比较是否降低峰值显存和贡献块存活时间。

### 验证实验

- 固定符号规模，逐步提高延迟率；
- 链形、星形和平衡树；
- 多个孩子同时向同一父节点传递延迟；
- 预估严重偏小和严重偏大；
- 接近显存上限的压力测试；
- 普通按需分配、异步池、一次定尺和边界分离对比。

### 阶段门槛

- 运行过程中不发生未受控的波前反复扩容；
- 节点启动后始终有空间保存最坏情况输出，或能够安全回退；
- 内存池能够报告峰值、碎片、扩容、迁移和等待时间；
- 延迟感知方案相对基础分配方案产生可测量的收益。

## 十二、阶段 10：实现任意人工消去树和任务调度

### 目标

从两层树推广到任意树，先不接入真实稀疏矩阵。

### 开发内容

1. ready queue；
2. `pending_children` 计数；
3. 节点状态机；
4. 多个独立子树并行；
5. 单个父节点使用唯一装配流；
6. 大节点和小节点的优先级；
7. 内存准入和任务准入联合调度；
8. 根节点结束状态；
9. 异常和显存不足传播。

建议状态机为：

```text
WAIT_CHILDREN
    ↓
READY_TO_ASSEMBLE
    ↓
ASSEMBLING
    ↓
READY_TO_FACTOR
    ↓
FACTORING
    ↓
OUTPUT_READY
    ↓
DONE
```

### 验证实验

- 链形树：验证延迟变量多层传播；
- 星形树：验证大量子贡献装配；
- 平衡树：验证分支并行；
- 极不平衡树：验证关键路径；
- 人工设置不同波前大小和延迟率；
- 比较单流和多流结果一致性。

### 阶段门槛

- 任意人工树均能正确结束；
- 不存在父节点提前执行；
- 不存在贡献块提前释放；
- 多流与单流产生等价数值结果；
- 调度日志能够解释每个节点的生命周期。

---

## 十三、阶段 11：接入真实稀疏矩阵和 CPU 分析阶段

### 目标

把人工消去树替换成由真实稀疏矩阵产生的排序、消去树和超节点。

### 开发内容

1. 稀疏矩阵读取和预处理；
2. CPU 排序；
3. 消去树构造；
4. 超节点识别；
5. 符号行列结构；
6. 原始矩阵到叶子或各超节点的数值装配；
7. 符号规模和初始内存估计；
8. 将分析结果转换成 GPU 描述符。

建议先使用保存好的分析结果文件进行调试，避免每次修改 GPU 数值代码时同时改变排序和超节点结构。分析接口稳定后，再接入在线 CPU 分析流程。

### 验证实验

- 小型稀疏矩阵手工验证消去树；
- 无延迟情况下与 CPU 稀疏分解比较；
- 检查每个原始非零元是否只被正确装配；
- 检查符号预测和实际波前规模；
- 检查真实矩阵产生的延迟分布。

### 阶段门槛

- 能从稀疏矩阵自动生成 GPU 数值任务图；
- 小矩阵全局因子可重构原矩阵；
- 分析阶段和数值阶段拥有清晰、稳定的数据接口。

## 十四、阶段 12：完成全局 GPU 数值分解

### 目标

完成从叶节点到根节点的完整数值分解，不再依赖人工波前输入。

### 开发内容

1. 原始数值装配；
2. 消去树调度；
3. 超节点分解；
4. 延迟主元向上传递；
5. 贡献块 extend-add；
6. 根节点处理；
7. 因子持久化；
8. 数值奇异状态；
9. 内存不足和回退状态；
10. 完整分解统计信息。

### 验证实验

- 与 CPU 全局参考流程比较；
- 小矩阵显式重构；
- 中大矩阵使用随机向量检查分解关系；
- 统计每层延迟主元；
- 检查最终因子规模与实际峰值显存；
- 根节点仍有延迟变量时正确报告奇异或失败。

### 阶段门槛

- 至少一类矩阵完成 GPU 全局分解；
- 因子能够用于后续求解；
- 分解失败有明确状态，不能静默返回错误因子；
- 能分阶段报告装配、分解、贡献传播和内存管理时间。

## 十五、阶段 13：实现 GPU 前代、回代和迭代改进

### 目标

形成真正的 \(Ax=b\) 端到端求解闭环。

### 开发顺序

1. 单右端项前代；
2. 对角块求解；
3. 单右端项回代；
4. 行列置换恢复；
5. 多右端项；
6. GPU 残差计算；
7. 迭代改进；
8. 多次求解时因子复用。

### 验证实验

- 先随机生成真解 \(x_*\)，再构造 \(b=Ax_*\)；
- 比较 \(x_*\) 和计算解；
- 计算范数化后向误差；
- 分别验证 LU 和 \(LDL^T\) 的置换顺序；
- 单右端项和多右端项；
- 有无迭代改进；
- 重复使用同一因子求解多个右端项。

### 阶段门槛

- 完成分析、分解、前代、回代和残差的全流程；
- 后向误差与参考求解器相当；
- 因子保持 GPU 驻留时可以连续求解多个右端项；
- 分解和求解阶段的时间能够分别统计。

## 十六、阶段 14：性能优化

### 目标

在完整正确流程上优化，而不是继续改变数学语义。

### 优化顺序

1. 使用性能剖析工具确定真实瓶颈；
2. 减少不必要的 CPU--GPU 同步；
3. 减少小内核启动；
4. 小超节点使用融合或批处理内核；
5. 中等超节点使用自定义面板加库函数；
6. 大超节点以 BLAS-3 为主；
7. 优化主元搜索和置换；
8. 优化 extend-add；
9. 调整面板宽度；
10. 调整流数量和任务优先级；
11. 调整内存预留和任务准入；
12. 优化前代和回代中的小三角块。

### 验证要求

每次优化都必须同时报告：

- 优化前后时间；
- 数值误差；
- 延迟主元数量；
- 峰值显存；
- 是否改变任务并发；
- 是否只对某一类矩阵有效。

### 阶段门槛

- 性能结论来自剖析数据而不是主观判断；
- 优化没有改变算法结果或稳定性；
- 找到小、中、大超节点的执行分界。

## 十七、阶段 15：正式论文实验顺序

正式实验不要混杂进行，按照以下顺序冻结结果。

### 15.1 正确性实验

1. CPU 算子正确性；
2. CUDA 单波前正确性；
3. 两层父子传播正确性；
4. 任意人工树正确性；
5. 真实稀疏矩阵全局分解正确性；
6. 前代、回代和后向误差。

正确性结果冻结后再开始正式性能实验。

### 15.2 单波前算子性能实验

1. 非分块 CPU；
2. 分块 CPU；
3. CUDA；
4. LAPACK 或功能兼容的库算子；
5. 扫描矩阵阶数；
6. 扫描面板宽度；
7. 扫描延迟率；
8. 统计主元搜索、置换和更新的时间比例。

### 15.3 内存管理实验

按照以下顺序比较：

1. 每次普通动态分配；
2. CUDA 异步内存池；
3. 分生命周期内存池；
4. 延迟后一次定尺；
5. 加入内存准入；
6. 加入核心区和延迟边界分离。

报告峰值显存、分配次数、迁移字节数、碎片率、等待时间和可求解最大规模。

### 15.4 全局数值分解实验

1. 无延迟或低延迟矩阵；
2. 中等延迟矩阵；
3. 高延迟和恶意矩阵；
4. 不同消去树形状；
5. 不同超节点规模分布；
6. 与 CPU 和成熟 GPU 求解器比较。

### 15.5 前代与回代实验

1. 单右端项；
2. 多右端项；
3. 因子留在 GPU；
4. 因子重新传输；
5. 多次求解的成本摊销；
6. 有无迭代改进。

### 15.6 端到端实验

分别报告：

1. 仅数值分解；
2. 分解加一次求解；
3. 分析加分解加求解；
4. 分析、分解、求解和迭代改进；
5. 一次分解加多个右端项。

### 15.7 消融实验

按照模块逐个移除：

- 延迟替代列策略；
- 自适应面板终止；
- \(W_P=L_PD_P\)；
- 自定义小超节点内核；
- 多流调度；
- 内存准入；
- 核心区和延迟边界分离；
- 迭代改进。

### 15.8 参数敏感性实验

- 主元阈值；
- \(2\times2\) 稳定阈值；
- 面板宽度；
- 小、中、大超节点分界；
- CUDA 流数量；
- 内存预算；
- 预留比例；
- 内存池尺寸等级。

### 15.9 压力与失败实验

- 连续延迟主元；
- 延迟变量跨越多层；
- 高扇入父节点；
- 接近显存上限；

- 根节点仍有延迟；
- 内存分配失败；

## 十九、建议的最小可交付路径

如果开发时间受到限制，按下面的优先级收缩：

```text
第一优先级：对称 CPU 算子正确性
    ↓
第二优先级：对称单波前 CUDA 算子
    ↓
第三优先级：两层父子延迟传播
    ↓
第四优先级：延迟物化和一次定尺内存管理
    ↓
第五优先级：任意消去树 GPU 分解
    ↓
第六优先级：前代和回代
    ↓
第七优先级：核心区和延迟边界分离
    ↓
第八优先级：非对称路线完整端到端
    ↓
第九优先级：多 GPU 和 MPI
```

硕士论文最需要避免的是：两个算子都完成了 CUDA 稠密演示，但没有任何一条路线完成父子传播、全局分解和回代求解。完整闭环的价值高于同时保留多条未完成的工程路线。
