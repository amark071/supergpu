#  面向 CUDA 的动态延迟主元超节点稀疏直接求解方法

## 一、论文定位

### 1. 研究对象

研究带动态延迟主元的超节点稀疏直接求解方法，并实现从数值分解到三角求解的单 GPU 端到端流程。论文同时考虑两类矩阵：

1. 一般非对称矩阵的超节点 LU 分解；
2. 实对称不定矩阵的超节点 Bunch--Kaufman \(LDL^T\) 分解。

论文中的“超节点算子”特指作用于一个超节点或波前稠密工作块的数值算子。全局求解器还必须包含消去树上的组装、贡献块传递、因子存储以及前代和回代，不能把单个稠密矩阵算子直接等同于完整的超节点求解器。

### 2. 核心科学问题

延迟主元会动态改变超节点的实际消去宽度、贡献块尺寸和父节点候选主元集合，而 GPU 高效计算要求规则、连续且规模可预期的稠密块。论文研究的核心矛盾是：

> 如何在保证主元选择正确性和数值稳定性的同时，控制延迟主元造成的结构与内存动态性，并保持超节点块计算在 GPU 上的并行效率。

### 3. 拟研究内容

1. 形式化非对称延迟 LU 与对称延迟 Bunch--Kaufman 两个超节点算子；
2. 设计延迟感知的 GPU 超节点内存管理机制；
3. 设计面向不同超节点规模的 CUDA 数值内核与任务执行流程；
4. 实现单 GPU 驻留的数值分解、贡献块传播、因子存储、前代和回代；
5. 从数值可靠性、运行性能和显存效率三个方面完成实验验证。

### 4. 建议的研究边界

- CPU 负责排序、消去树和超节点划分等分析阶段；
- GPU 负责数值组装、主元选择、分解更新、贡献块处理和三角求解；
- 以双精度、单 GPU 为论文主体；
- 多 GPU、MPI、BLR 压缩和 GPU 排序作为后续工作；
- MUMPS 用于理解延迟主元、波前组装和内存管理机制，并作为 CPU 对照，不要求直接重写整个 MUMPS；
- 论文所称“端到端 GPU”是指数值阶段端到端 GPU 驻留，而不是排序和符号分析也必须运行在 GPU 上。

### 5. 需要先统一的算法定义

当前说明文档与 CPU 实现之间存在一个需要在论文中明确区分的条件：

- 说明文档一处使用 \(\alpha_k<\tau\beta_k\) 表示当前列主元未通过阈值检验；
- 当前非对称 CPU 实现只在 \(\alpha_k=0\)，即当前活动列全零时，搜索替代列或产生延迟后缀。

两种情况不能等同。\(\alpha_k<\tau\beta_k\) 并不推出当前列全零，也不能直接使用“该列后续不会被更新”的论证。论文应明确选择以下一种定义，或把它们作为两种策略分别研究：

1. **结构性延迟：**仅当当前活动列为数值零时延迟；
2. **阈值延迟：**当主元未通过稳定性阈值时延迟，需要重新论证更新、终止和稳定性；
3. **混合策略：**非零但不稳定的列采用阈值延迟，全零列采用快速替代列搜索。

CPU 与 CUDA 实现、伪代码、正确性证明和实验参数必须使用同一套定义。

## 第 1 章 绪论

### 1.1 研究背景与意义

- 大规模稀疏线性方程组及稀疏直接法的应用；
- 超节点方法利用 BLAS-3 提高计算强度的基本思想；
- 不稳定或奇异局部主元对稀疏分解的影响；
- 延迟主元对数值稳定性、填充、计算量和内存预测的影响；
- GPU 规则块计算与动态延迟主元之间的矛盾。

### 1.2 国内外研究现状

- 稀疏 LU、\(LDL^T\) 与超节点方法；
- 多波前方法、波前矩阵和贡献块；
- 部分选主元、阈值选主元、Bunch--Kaufman 与延迟主元；
- MUMPS、SuperLU、STRUMPACK、cuDSS 等稀疏直接求解器；
- GPU 稀疏直接法的算子、调度与内存管理研究；
- 现有方法在动态主元和 GPU 驻留方面的不足。

### 1.3 研究问题与技术难点

- 延迟发生后如何保持局部分解关系正确；

- 如何预测动态波前或超节点的实际存储量；
- 如何减少 GPU 上的重新分配、数据搬迁和同步；
- 如何兼顾小超节点延迟敏感操作与大矩阵 BLAS-3 更新。

### 1.4 主要研究内容与拟创新点

- 非对称延迟 LU 超节点算子；
- 对称不定延迟 Bunch--Kaufman 超节点算子；
- 延迟感知的 GPU 分级内存池与容量管理；
- 单 GPU 端到端数值分解和求解流程；
- 面向延迟率和超节点规模的自适应执行策略。

这一节在最终论文中应使用“提出”“实现”还是“验证”，以最终完成情况为准，不能提前将计划写成已经成立的创新。

## 第 3 章 动态延迟主元超节点分解算子

### 3.1 统一的超节点活动区模型

维护连续的四段式状态：

```text
[0, panel_begin)          已完成并写回的面板
[panel_begin, k)          当前面板已接受的主元
[k, active_end)           尚可参与主元选择的变量
[active_end, n)           延迟变量
```

说明置换、全局编号、局部编号、主元元数据和延迟后缀必须同步更新。

### 3.2 非对称延迟主元 LU 算子

#### 3.2.1 局部波前分块

- Fully-Summed 块；
- 已消去因子块；
- 延迟变量与普通更新变量；
- 扩展贡献块。

#### 3.2.2 主元选择与列置换

- 当前列部分选主元；
- 全零列的判定；
- 全局最大元回退策略；
- 从活动区尾部寻找首个可用列的快速策略；
- 行、列置换记录和 \(PAQ=LU\) 关系。

#### 3.2.3 延迟后缀的形成

- 当前列与替代列交换；
- 防止已经延迟的列重新进入活动区；
- 找不到可用列时的终止条件；
- 延迟区作为贡献块一部分向父节点传递。

#### 3.2.4 自适应 KJI-SAXPY 面板分解

- 面板内部只物化主元选择需要的列；
- 面板完成后的 TRSM 与 GEMM 更新；
- 延迟事件触发面板提前结束和更新写回；

#### 3.2.5 正确性与复杂度

- 主元搜索、置换、面板更新和贡献块形成的复杂度。

### 3.3 对称不定延迟 Bunch--Kaufman 算子

#### 3.3.2 对称置换与紧凑存储

- 延迟后缀与贡献块的对称性。

#### 3.3.3 混合主元块面板

- 面板不得分割 \(2\times2\) 主元块；

## 三、实验大纲

## 1. 实验研究问题

### RQ1：两个延迟主元算子是否正确且数值可靠？

- 是否满足带置换的部分或完整分解关系；
- 延迟前缀、延迟后缀和置换元数据是否正确；
- 与 LAPACK 结果相比，后向误差和主元增长是否处于可接受范围；
- 对称算法是否正确处理混合 \(1\times1/2\times2\) 主元。

### RQ2：分块算子能否把主要计算转化为 BLAS-3/CUDA 大块运算？

- 分块版本相对非分块版本的加速；
- 面板宽度与性能的关系；
- 延迟事件导致的面板提前结束有多少额外代价；
- 不同矩阵规模和延迟率下 GPU 的有效区间。

### RQ3：延迟感知内存管理能否降低峰值显存和数据迁移？

- 与逐超节点动态分配相比是否减少分配次数；
- 与固定比例过量预留相比是否降低显存浪费；
- 是否减少整体搬迁、压缩和 CPU--GPU 传输；
- 在高延迟率下是否仍能避免非必要的显存不足。

### RQ4：完整 CUDA 数值流程能否获得端到端收益？

- 分解、前代、回代分别获得多少加速；
- 组装、调度和数据传输是否抵消内核加速；
- 对哪些超节点规模和矩阵类型有效；
- 与成熟 CPU/GPU 求解器相比处于什么位置。

## 5. 正确性与数值稳定性实验

### 5.1 非对称部分分解验证

若成功消去 \(r\) 个变量，应验证

\[
PAQ=
\begin{bmatrix}
L_{11}&0\\
L_{21}&I
\end{bmatrix}
\begin{bmatrix}
U_{11}&U_{12}\\
0&S
\end{bmatrix},
\]

其中 \(S\) 包含尚未消去的活动或延迟部分。报告相对重构误差

\[
e_{\mathrm{fac}}=
\frac{\|PAQ-\widehat L\widehat U\|_F}{\|A\|_F}.
\]

### 5.2 对称部分分解验证

验证

\[
P^TAP=
\begin{bmatrix}
L_{11}&0\\
L_{21}&I
\end{bmatrix}
\begin{bmatrix}
D_{11}&0\\
0&S
\end{bmatrix}
\begin{bmatrix}
L_{11}^T&L_{21}^T\\
0&I
\end{bmatrix}.
\]

同时检查：

- \(D_{11}\) 只包含合法的 \(1\times1/2\times2\) 块；
- 延迟后缀在完成面板更新后仍是正确的 Schur 补；
- 对称置换和原始变量编号一致；
- 完整分解时因子给出的惯性与参考结果一致。

### 5.3 完整求解验证

对成功完成的非奇异系统报告范数化后向误差

\[
e_{\mathrm{back}}=
\frac{\|b-A\widehat x\|}
{\|A\|\,\|\widehat x\|+\|b\|}.
\]

附加报告：

- 主元增长因子；
- 延迟主元总数和最大传播层数；
- \(1\times1\) 与 \(2\times2\) 主元数量；
- 迭代改进次数；
- 成功、数值奇异、内存不足和其他失败状态。

## 四、阶段性实施与验收标准

## 阶段 0：冻结 CPU 数学参考实现

### 工作内容

- 统一零列延迟与阈值延迟的定义；
- 补齐两种算子的部分分解重构检查；
- 固定随机测试、恶意算例和性能测试；
- 输出机器可读的因子、置换、延迟区和误差结果。

### 验收标准

- CPU 测试可重复；
- 两个算子在测试集中满足预设误差阈值；
- 非分块与分块结果在算法允许的范围内一致；
- 延迟后缀的 Schur 补关系被直接验证。

## 阶段 1：CUDA 单超节点算子

### 工作内容

- 先移植矩阵更新和面板计算；
- 再实现主元搜索、置换和延迟控制；
- 建立 CPU/CUDA 双路径测试；
- 找到不同规模下的执行策略。

### 验收标准

- CUDA 算子通过 CPU 参考测试；
- 能正确处理连续延迟和混合主元块；
- 中大规模算子的主要时间进入 BLAS-3 或等价 CUDA 内核；
- 明确 GPU 优于 CPU 的规模区间。

## 阶段 2：消去树与延迟感知内存管理

### 工作内容

- 实现超节点描述符和 GPU 内存池；
- 实现贡献块 extend-add；
- 实现延迟变量扩充父节点；
- 实现波前生命周期和依赖管理。

### 验收标准

- 多层人工消去树数值结果正确；
- 无并发覆盖和提前释放；
- 与按需动态分配相比，分配次数和迁移量显著下降；
- 接近显存容量时能够成功回收或安全失败。

## 阶段 3：完整数值分解与求解

### 工作内容

- 接入真实稀疏矩阵和 CPU 符号分析结果；
- 完成根节点处理和因子持久化；
- 完成前代、回代和置换；
- 完成残差和迭代改进。

### 验收标准

- 对非奇异测试矩阵完成 \(Ax=b\) 全流程；
- 后向误差与参考求解器相当；
- 延迟变量能够在父节点重新参与主元选择；
- 报告分解、求解、内存和端到端时间。

## 阶段 4：实验收敛与论文写作

### 工作内容

- 固定正式测试矩阵和对照版本；
- 运行消融、敏感性和压力实验；
- 分析失败矩阵和适用边界；
- 将代码版本、参数和原始结果归档。

### 最低论文闭环

论文至少需要形成以下闭环：

1. 两个 CPU 算子有明确数学定义和正确性验证；
2. 至少一个算子完成稳定的 CUDA 超节点实现；
3. 延迟感知内存管理进入真实的父子超节点传播流程；
4. 至少一类矩阵完成 GPU 数值分解、前代和回代；
5. 实验同时给出数值误差、延迟行为、显存和端到端性能。

理想闭环是两类矩阵均完成端到端 GPU 求解；如果时间不足，应优先确保一条主线完整，而不是保留两个只完成单超节点演示的半成品流程。
